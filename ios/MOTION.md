# 動畫與回饋規矩

新增或修改畫面上的動畫、轉場、手勢、觸覺時讀這份。目標是整個 App 的手感一致：同一種事件，在哪個畫面都用同一種動法。

## 參數

- 動畫曲線的正本是 `DayDo/Components/Motion.swift`，依用途命名（按壓、分頁、抽屜、列表重排、打勾、數字…），每個 token 都含「減少動態效果」時的替代動畫。畫面裡不寫裸的 `.spring(…)`、`.snappy`、`.easeOut(…)`；`DayDoCore/Tests/DayDoCoreTests/ArchitectureTests.swift` 會擋。
- 新動畫先找用途相同的 token。真的是新用途才在 `Motion.swift` 加一個，不為單一畫面微調數字；要改手感就改 token，全 App 一起變。
- 非畫面的程式要等動畫做完（例如完成任務的樂觀狀態要保留到列收起）時，等待時間跟著對應的 token 定義在 `Motion.swift`（如 `Motion.layoutSettle`），不在呼叫端寫死毫秒。
- 手勢的距離門檻、速度判斷、彈回條件留在各畫面，不抽成通用元件；它們只共用 token 的曲線。

## 每種變化都要有過渡

- 資料變動（新增、完成、刪除、延期、搬清單）要包在動畫裡，列加進出轉場。第一次載入與切換清單不動畫，否則整片列表會飛進來。
- 數字變動用 `.contentTransition(.numericText())`。
- 可點的元件用 `.buttonStyle(.press)`（按下縮小、放開回彈），新增的不用 `.plain`。
- 使用者的動作先改畫面再寫入：勾選先打勾，停一下才收起這一列。

## 手勢要跟手

拖曳過程中，內容跟著手指走；放手後依位移和速度決定完成或彈回。不要等放手才開始播動畫（抽屜左緣滑開、日曆換頁與收合都照這個做）。

邊緣手勢的 UI 測試要從實機大拇指會落的位置（約 30pt）起手：抽屜左緣原本只收 24pt，測試從 8pt 拉一直過，實機卻拉不出來。

## 觸覺

一律用 `.sensoryFeedback`，依事件挑：

| 事件 | 回饋 |
|---|---|
| 完成任務 | `.success` |
| 刪除任務 | `.impact(weight: .medium)` |
| 取消完成、點 ＋ 新增按鈕、建立任務、延期任務、還原任務、開合抽屜、日曆換頁、拖曳開始 | `.impact(weight: .light)` |
| 選取（分頁、日期、模式、拖曳對齊刻度） | `.selection` |

## 驗收

- 動畫改動用 `ios/scripts/record-uitest.sh` 錄下對應的 UI 測試，用 ffmpeg 抽格逐格看（指令在腳本開頭）。`shot()` 的截圖拍在動畫結束之後，證明不了過渡有沒有發生：曾經截圖看起來正常，錄影才看到勾勾在淡出時退回未勾。
- 要證明「沒有閃一下」時，用錄影原生的 60fps 逐格看。15fps 抽格每格約 66ms，曾漏掉啟動時 16–33ms 的狀態列黑字，誤判為已修好。
- 新加的轉場也要有「減少動態效果」版本：位移和縮放換成淡入淡出，不能完全沒有回饋。
